# --- gcc -fanalyzer ------------------------------------------------------
# The three "leak of 'nb'" findings are the same pattern in three files: a buffer that grows with
# realloc. When the realloc fails, the old buffer stays in the struct and the function returns
# false; the buffer is freed by the function's own deinit. The analyzer cannot see that the
# struct still owns it, so it reports the old block as leaked. Read and accepted as false
# positives.

gcc-fanalyzer | service/adapter/src/fractalsql_vector.c | -Wanalyzer-malloc-leak | 1 | false positive: the realloc keeps the old buffer in the struct, and the struct's deinit frees it
